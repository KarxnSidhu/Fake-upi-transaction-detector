    A few things worth knowing
    Does “no obvious anomaly” mean the payment is real?
    No. A manipulated screenshot can look convincing. The result describes available image checks, not whether money arrived in your account.
    What is the signal score?
    A combination of heuristic warning signals from the backend. It is not a calibrated probability or a guarantee. Read missing checks and explanations alongside the number.
    Why did a screenshot get flagged again?
    The server checks image and transaction fingerprints against its scan history. Rescanning a genuine receipt can trigger a reuse warning. Compare with your records.
    What happens to the screenshot?
    The application does not retain images as scan history. The server stores metadata and hashes for duplicate checks. Reports you download may contain OCR text and transaction details; keep them private.
    What if the camera or analysis is unavailable?
    Use Browse files to select an existing screenshot. If the service is offline, retry the connection. If OCR or reference checks are unavailable, use your bank records to verify payment.
    Who can see scan history?
    This prototype has shared server history and no user accounts. Use it only in a trusted environment. History is not separated by merchant.
